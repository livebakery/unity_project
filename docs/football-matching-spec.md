# Football Matching App — เอกสารสเปค (MVP)

> สถานะ: **Draft v0.1** — เอกสารสำหรับรีวิว/ปรับก่อนเริ่มพัฒนา
> ขอบเขต MVP: **กรุงเทพฯ**, แผนที่ **Google Maps**, platform **LINE (LIFF) + Web**

---

## 1. ภาพรวม (Overview)

แอปสำหรับ **จับคู่คนเตะบอล** กับ **ก๊วน/นัดเตะ** ในกรุงเทพฯ โดยรวบรวม "นัดเตะ" ที่กระจัดกระจายอยู่ตามโพสต์ Facebook/LINE ให้มาอยู่ในที่เดียวที่ **ค้นหาได้ แยกโซน-เขตได้ และดูตำแหน่งสนามบนแผนที่ได้**

หัวใจของแอป: ผู้ใช้ **วางข้อความโพสต์** (จาก FB/LINE) → **AI ช่วยแตกเป็นข้อมูลที่ค้นหาได้** (วันเวลา, สนาม, โซน, จำนวนคนที่ขาด, ตำแหน่ง, ราคา, ช่องทางติดต่อ) แทนที่จะให้คนกรอกฟอร์มยาวๆ เอง

---

## 2. ปัญหาที่แก้ (Problem statement)

ยืนยันจากผู้ใช้แล้วทั้ง 3 ข้อ:

1. **โพสต์ใน Facebook เลื่อนหาย/หายาก** — อยากเตะคืนนี้ แต่กว่าจะหาเจอว่าก๊วนไหนยังขาดคนก็ยาก โพสต์จมฟีดเร็ว
2. **ไม่รู้ว่าสนามไหนอยู่ตรงไหน / ว่างไหม** — ต้องไล่ถามเอง ไม่มีภาพรวมสนามแถวบ้าน
3. **ไม่รู้ว่าก๊วนแถวบ้านมีตรงไหน** — คนนอกกลุ่ม FB ไม่เห็นโพสต์ หาเพื่อนเตะในโซนตัวเองยาก

---

## 3. กลุ่มผู้ใช้ (Personas) & Jobs-to-be-done

| Persona | สถานการณ์ | สิ่งที่ต้องการ |
|---|---|---|
| 🧍 **คนหาก๊วนไปเติม** | เดี่ยว/กลุ่มเล็ก อยากไปแจมคืนนี้ | เปิดมาเห็น "ก๊วนใกล้ฉัน คืนนี้ ที่ยังขาดคน" กดติดต่อได้เลย |
| 👥 **หัวหน้าก๊วนหาคนเติม** | จองสนามแล้ว ขาดอีก 3 คน | โพสต์ทีเดียว คนในโซนเห็น ไม่ต้องสแปมหลายกลุ่ม |
| 🗺️ **ทั้งคู่** | ไม่คุ้นพื้นที่ | รู้พิกัดสนาม กดนำทาง Google Maps ได้ทันที |

**ขอบเขต MVP รองรับทั้งสองฝั่ง** (หาคน + หาก๊วน)

---

## 4. ขอบเขต MVP (Scope)

### ✅ In scope (Phase 1)
- สร้าง "นัดเตะ (Match)" โดย **วางข้อความ → AI parse** เป็น field
- แก้ไข field ที่ AI แตกมาได้ก่อนโพสต์ (human-in-the-loop)
- หน้า list นัดเตะ + **filter**: โซน/เขต, วัน, ช่วงเวลา, ประเภท (5/7/11 คน), ระดับฝีเท้า, จำนวนที่ขาด
- เรียงตาม **"ใกล้ฉัน"** (ระยะจากตำแหน่งผู้ใช้)
- **แผนที่ Google Maps** แสดง pin สนาม + กดนำทาง
- คลังข้อมูล **สนาม (Venue)** ใช้ซ้ำได้ + พิกัด/ลิงก์ Google Maps
- การ์ดนัด **หมดอายุอัตโนมัติ** หลังเวลาเตะ (ฟีดไม่รก)
- ติดต่อหัวหน้าก๊วนผ่านลิงก์ LINE/โทร

### 🚫 Out of scope (ไว้ Phase ถัดไป)
- ดึงโพสต์อัตโนมัติจาก Facebook group **(ดูหัวข้อ 9 — ข้อจำกัด/ข้อกฎหมาย)**
- ระบบจ่ายเงิน/หารค่าสนามในแอป
- ระบบจับคู่อัตโนมัติเต็มรูปแบบ + rating/รีวิว
- แชทในแอป (ใช้ deep link ไป LINE แทนก่อน)

## 5. ฟีเจอร์หลัก (Features)

### 5.1 สร้างนัดเตะจากการวางข้อความ (หัวใจของแอป)
- ช่อง textarea: ผู้ใช้วางข้อความโพสต์จาก FB/LINE
- เรียก **Claude API** แตกเป็น JSON: วันเวลา, ชื่อสนาม, โซน/เขต, ประเภท (5/7/11), จำนวนที่ขาด, ตำแหน่งที่ต้องการ (GK/กองหลัง/กองหน้า), ราคาหารหัว, ระดับฝีเท้า, ช่องทางติดต่อ
- แสดงผลให้ผู้ใช้ **ตรวจ/แก้** ก่อนกดโพสต์
- ถ้าจับชื่อสนามได้ → ค้นใน Venue เดิม / ถ้าไม่มี → geocode ด้วย Google Maps แล้วสร้าง Venue ใหม่

### 5.2 ค้นหา & filter
- Filter: เขต (กทม. 50 เขต), วัน, ช่วงเวลา (เช้า/เย็น/ดึก), ประเภททีม, ระดับ, สถานะยังขาดคน
- Sort: ใกล้ฉัน / เวลาใกล้ถึง / โพสต์ล่าสุด

### 5.3 แผนที่สนาม (Google Maps)
- Map view แสดง pin ทุกสนามที่มีนัดเปิดอยู่
- กด pin → เห็นนัดที่สนามนั้น + ปุ่มนำทาง (Google Maps deep link)
- ใช้ Google Maps JavaScript API + Geocoding API + Places API (autocomplete ชื่อสนาม)

### 5.4 โปรไฟล์ผู้ใช้ (เบื้องต้น)
- โซนที่สนใจ, ตำแหน่งที่เล่น, ระดับฝีเท้า → ใช้ทำ default filter + (อนาคต) noti

## 6. Data Model

```
User
  id, display_name, line_user_id?, avatar
  home_zone (district), preferred_positions[], skill_level
  created_at

Venue (สนาม — แยกตารางเพื่อ reuse + ขึ้น map)
  id, name, address
  lat, lng, gmaps_place_id, gmaps_url
  district, province (default: กรุงเทพมหานคร)
  pitch_types[] (5/7/11), indoor/outdoor
  created_at

Match (นัดเตะ — การ์ดหลัก)
  id, host_user_id
  venue_id  → Venue
  kickoff_at (datetime), duration_min
  match_type (5 | 7 | 11)
  players_needed (int), positions_needed[]
  price_per_head (nullable)
  skill_level (beginner | intermediate | advanced | any)
  contact_line, contact_tel
  raw_text (ข้อความต้นฉบับที่วางมา)
  status (open | full | expired | cancelled)
  expires_at (= kickoff_at + duration; auto-expire)
  created_at, updated_at

JoinRequest (Phase 2 — คนกดขอเข้าร่วม)
  id, match_id, user_id, status (pending|accepted|declined), created_at
```

หมายเหตุ: เก็บ `raw_text` ไว้เสมอ เพื่อ (1) ให้ผู้ใช้ตรวจย้อนได้ (2) ใช้ปรับปรุง prompt ของ parser

## 7. สถาปัตยกรรม & Tech stack

```
┌─────────────────────────────────────────────┐
│  Client: Next.js (App Router)                │
│   - เปิดบน Web ปกติ + ฝังเป็น LINE LIFF       │
│   - Google Maps JS API (map + autocomplete)   │
└───────────────┬─────────────────────────────┘
                │
┌───────────────▼─────────────────────────────┐
│  API routes / Server (Next.js)               │
│   - /api/parse   → เรียก Claude API           │
│   - /api/matches → CRUD + filter + geo sort   │
│   - /api/venues  → geocode + cache            │
│   - cron: expire matches                      │
└───────────────┬─────────────────────────────┘
                │
┌───────────────▼─────────────────────────────┐
│  Postgres (Supabase) — Match / Venue / User  │
└──────────────────────────────────────────────┘
```

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| Frontend/Backend | **Next.js** | เว็บ + LIFF ในโค้ดเดียว, API routes ในตัว |
| Database | **Postgres (Supabase)** | free tier, auth/พิกัด (PostGIS) พร้อม |
| แผนที่ | **Google Maps** | ตามที่เลือก — Places autocomplete ชื่อสนามแม่นในไทย |
| AI parser | **Claude API** | แตกข้อความไทยเป็น structured JSON |
| Auth | **LINE Login** (Phase 2) | คนเตะบอลไทยใช้ LINE อยู่แล้ว |
| Hosting | Vercel | deploy ง่าย, cron ในตัว |

## 8. การแยกโซน/เขต (กรุงเทพฯ)

- ใช้ **50 เขตของ กทม.** เป็น taxonomy หลัก (เก็บเป็น enum/lookup table)
- จัด **กลุ่มโซน** เพื่อ filter หยาบ: กทม. ชั้นใน / เหนือ / ใต้ / ตะวันออก / ตะวันตก / ธนบุรี
- map เขต ↔ พิกัด: derive จาก `lat/lng` ของ Venue ด้วย reverse-geocoding (Google) ตอนสร้าง Venue → ไม่ต้องให้ผู้ใช้เลือกเขตเอง
- เผื่ออนาคต: ขยายเป็นจังหวัด (มี field `province` ไว้แล้ว)

## 9. ข้อจำกัด & ข้อกฎหมาย (สำคัญ — อ่านก่อน)

### ทำไมไม่ดึงโพสต์อัตโนมัติจาก FB group
- **Facebook Graph API** อ่านโพสต์ในกลุ่มได้เฉพาะกลุ่มที่แอดมินติดตั้งแอปเรา + ผ่าน Meta App Review เท่านั้น
- **Scraping / บัญชีปลอมอัตโนมัติ** ผิด ToS ของ Facebook อย่างชัดเจน, เสี่ยงผิดกฎหมาย (เข้าถึงระบบโดยไม่ได้รับอนุญาต / ปลอมตัวตน) และ **สร้างฐานข้อมูลที่ไม่ยั่งยืน** (โดนล้างเป็นรอบๆ) — **ไม่อยู่ในแผนพัฒนา**

### วิธีได้ข้อมูลที่ทำได้จริง (ตามลำดับแนะนำ)
1. **ผู้ใช้แชร์/วางเข้าระบบเอง** → AI parse (= MVP นี้) ✅ ถูกกฎ 100% และเป็นหัวใจที่ทำให้แอปมีคุณค่า
2. **สร้างกลุ่ม/เพจของเราเอง** แล้วใช้ Graph API อ่านได้เต็มที่ (เราเป็นแอดมิน)
3. **Partner กับแอดมินกลุ่มดังๆ** ให้ยินยอม + ติดตั้งแอป (ต้องผ่าน App Review)

### PDPA
- ข้อมูลติดต่อ (เบอร์/LINE) มาจากการที่ผู้ใช้ **โพสต์เอง** = มีฐานความยินยอม
- มีปุ่มลบนัด/ลบข้อมูลตัวเองได้
- ไม่เก็บข้อมูลบุคคลที่สามที่ไม่ได้ยินยอม
